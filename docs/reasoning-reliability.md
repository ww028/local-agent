# 本地模型推理可靠性：实现、实验与未解决项

## 目的与结论

让读者知道为什么不能把“有思考开关”当成推理正确率提高。当前正式路径只增加有限精确校验；常识与逻辑陷阱题尚未解决。实验使用本机 `qwen3:14b`、Ollama、8192 上下文；题集只有7道，不是标准基准或泛化能力证明。

## 正式实现

- `ChatRequest.reasoning` 默认 false；快速回答走普通模型流。
- 深度模式预留 `min(4096, num_ctx // 2)` 输出，并在系统提示加入按题目条件检查结论的约束；Agent 模式当前不支持深度模式。
- `routes/chats.py`：只有 reasoning=true、自由对话、未启用知识库时尝试 `answer_review.exact_answer(text)`。
- 完整匹配的两个十进制数字比较使用 `Decimal`；完整匹配的 ASCII 单词字母计数按字符实际位置计算，区分大小写。不匹配就回模型，不模糊猜测用户意图。
- 未开放任意 eval、没有查题答案表；该入口不是通用算术/中文计数/带单位比较工具。已有 Agent calculator 是另一条路径。
- 精确结果仍保存到正常会话；正式路由未调用实验函数 `reviewed_answer`。

## 实验及取舍

1. **只接通 think 与输出预算**：洗车题快速/深度均曾选走路，未证实提升。
2. **强调目标与必要对象**：模型仍可写出“车需到场”后选择走路，结论与过程矛盾。一次4096输出预算的 think 请求出现重复思考、无最终内容并以 length 结束；不保存原始隐藏思考。
3. **独立草稿审查**：单独候选测试曾纠正洗车题，但接完整聊天提示后的两轮7题测试仍错，且出现把正确答案改错。因此不接正式流。
4. **精确计算兜底**：比较和计数不需要模型猜，第二轮明确输出正确数值及位置。仅这些格式可视为已解决。

## 两轮实测观察（人工读结论，不以关键词判分）

| 题型 | 普通回答观察 | 第二轮精确/审查路径观察 | 状态 |
|---|---|---|---|
| 50米去洗车 | 选走路，未将车带到店 | 审查仍选走路 | 未解决 |
| 9.11与9.8 | 错认为9.11大 | Decimal给9.8大 | 已解决匹配格式 |
| strawberry 的 r | 答2个 | 精确计数3个，第3/8/9位 | 已解决匹配格式 |
| 足够大船装全部 | 先套经典限制，最终答1次 | 审查反改为7次 | 审查退化，不启用 |
| 无底、顶封闭杯倒置 | 认为不能装水 | 审查答能，解释上下互换 | 局部成功，非普遍证明 |
| 修自行车带对象 | 普通表述含矛盾 | 审查明确把车带到店 | 局部成功 |
| 只去洗车店咨询 | 普通答走路 | 审查反改为开车 | 对照题退化，不启用 |

第一轮计数审查虽然答3，却给错字母位置，说明“数字正确”不等于理由正确。两轮审查会退化，不能用局部成功掩盖整体风险。

## 可复跑入口与判分风险

运行 `backend/.venv/bin/python scripts/eval-reasoning.py`。脚本调用本地模型，不写用户会话，不下载模型、不外发题目；输出答案，不输出隐藏思考。普通分支是 temperature=0 的 compose_chat；review 分支为精确校验或两阶段非think审查，**不是正式深度模式的完整端到端评测**。

目前 `marker_match` 仅做字符串出现筛查。错误答案“9.11比9.8大”也匹配9.8，否定句也匹配开车。汇总的5/7、7/7不是正确率，不用于宣传。两轮原始输出未作为仓库文件保存，本页保留人工复核观察；后续应把可公开答案与参数保存成版本化报告。

## 下一步验收标准

- 精确比较/计数增加边界、负数、相等、大小写、额外限定不匹配的单测；现有108后端测试通过不代表这些边界已全覆盖。
- 评测保存模型版本、量化、参数、时间、输出、结论与理由判分，严格区分快速/think/精确/审查。
- 分开开发题与未见变式；包含洗车/咨询、带对象/仅问价等相反对照，防止提示硬套答案。
- 比较其他许可可用的本地模型，记录速度/内存/超时及正确性；不自动下载或改默认模型。
- 只有完整端到端结果证实不退化，才启用新策略。仍不能保证任意常识或主观语境题正确。
