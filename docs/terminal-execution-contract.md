# 终端意图—计划—执行—验证统一改造

## 目标
自然语言不是shell。模型理解和建议不能代替真实目标发现、权限确认或结果验证。保留生成式通用终端，但对具有可靠执行契约的能力统一走编译层，而非让模型猜PID或退出码。

## 层次与契约
1. 请求分类：观察/修改/终止，显式目标才编译。否定、条件、歧义及无数字追问不凭规则猜测，交回现有模型规划。
2. 能力编译层：查询端口与终止端口共享目标发现；查询生成逐端口机器字段lsof；终止先发现真实PID及启动身份，再生成TERM计划，不自动升级KILL。
3. 不可变计划：端口与进程身份绑定到计划hash。执行前核对计划时的身份，不只是确认后读取一次身份。目标变化拒绝，不自动重绑。
4. 执行层：保持原始退出码。正常无监听仅由端口适配器证明；不能把只读命令任意失败改成成功。
5. 验证与报告：目标验证通过、仍有监听、命令失败、无可见目标分别确定报告。无文本输出不等于未执行。未配置验证的通用命令仅报告命令状态，不宣称目标完成。

## 此批范围
建立共享能力规划入口，整合已有端口查询、版本快路径及新终止规划，消除终止依赖模型tool_calls的问题。无监听时只查询，不生成kill。保存计划时捕获身份，确认后身份变化拒绝。保留模型生成其他复杂命令；并非通用语义理解或所有业务效果验证器。

## 验证矩阵
显式单/多端口、无监听、否定/条件请求、旧PID、身份变化、查询无匹配、命令失败、TERM后仍监听、不自动强杀。自动单测与真实临时执行器测试分别记录；不重放用户任务。跨平台、OS沙箱、PID检查与信号竞态、复杂追问语义仍是未完成项。
