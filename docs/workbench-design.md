# 工作台体验与交付技术方案

## 用户路径

左侧导航(对话/知识库/执行记录)；聊天侧栏(搜索/新建/重命名/删除/导出)；
主区(模式/模型/参数/消息/引用/执行事件)。默认保持本地优先，能力与未实现
范围在空状态/帮助中说明，不用无作用的按钮充数。

## 方案

- 模式使用单选chat/knowledge/agent，避免两个checkbox的歧义。
- 会话ID入URL和本地状态(非敏感配置)，重进保持选择；历史服务端持久化。
- rename PATCH会话，标题1–100字；搜索前端过滤；Markdown导出由浏览器
  Blob生成，仅下载本机已有记录，不依赖服务端任意写路径。
- 参数temperature可选、num_predict有界(128–2048)；上下文仍由服务端
  统一预算，不能随便将本机内存上限开放成无限滑块。
- 已保存run_id的消息提供执行详情展开，重载时从/api/runs取事件；
  运行过程是模型步骤与工具动作摘要，不暴露内部推理。
- 知识来源打开文档ID/片段定位，显示标题及行号。模型列表过滤embedding
  类型，不能把bge-m3当聊天模型。模型缺失/索引失败提供明确说明与重试入口。
- 样式改成宽屏三栏、窄屏可收缩，内容区明确滚动；错误/忙碌/取消可见。

## 自测和交付

单测接口验证rename、导出只读、模式/参数边界、run详情；前端构建和SSE测试。
浏览器验收：导入→状态ready→预览→引用问答→跳来源→Agent工具运行→
重开详情→取消→再次发送→重命名/搜索/导出。真实模型测试记录与mock分开。
开源README写中文快速开始与范围，记录每个commit/模块push，交付可用入口
和验收说明；依赖/测试数据/模型不得混入Git。

## 明确不做

任意文件/命令执行、网搜、公司连接器、PDF/OCR、多人权限、无限全文处理。
这些留作后续方案。首版专注聊天、Markdown证据、只读工具Agent三个稳定闭环。
