## 终端窗口（会话式）验收

- 先写terminal-console-design；页面改为终端窗口：红黄绿标题栏、等宽字体、单条

  20条）与有界会话上下文（最多6条已结束任务，输出截断，标记不可信）。
- 真实本地模型：输入“查看一下我的电脑内存是多大的？”生成sysctl+awk两步骤计划，
  确认前0执行；在输入框输入`y`回车后两步完成，原始输出51539607552/48.00 GiB，
  [exit 0]，解释与事实一致。网页刷新/换页后结果仍在转录中。
- 输入`n`取消“看看这个仓库的 Git 状态”（计划/usr/bin/git status），status=cancelled、
  执行步骤0，未运行git。
- 追问“再看看现在内存还剩多少可用？”真实模型据此生成/usr/bin/vm_stat并确认执行；
  macOS分页统计原始输出保留，模型解释了free/active/wired等字段，没有把页数编造成
  单一可用GiB结论。这说明上下文能帮助理解追问，但仍可能不给最终换算。
- 自动用例覆盖转录时间顺序/条数上限、上下文长度与只含已结束任务、y/n解析为
  确认/取消、待确认时其他文本不误提交、原始输出/退出码/端口事实分区。
- 局限：输入框自由文本一定先经模型规划，不是交互式PTY；`y`是对屏幕固定计划的
  一次显式确认，不是通用授权；无OS沙箱/网络隔离；无sudo/密码/常驻服务。

## 未完成与风险

- 合成十几万字索引已实测；真实多格式长资料、长期稳定性与峰值内存尚未验收。
- 全文总结/多文档全量对照不能靠Top-K保证完整；第一版局部检索，不虚标。
- 物理断网未执行；运行请求本地、禁云配置检查不等于整机断网认证。
- 单机单用户：无账号、多租户ACL、审计/灾备、对公网生产部署。
- PDF/OCR/看图、专用网络/公司连接器未提供。生成式AI终端可以在明确确认后
  执行代码/脚本/写入/联网命令；这不是OS安全隔离，不保证任意命令可靠。
- Agent最终回答非流式（工具事件实时），限6步/8调用/120秒；小模型可能需
  明确任务指令。工具决策可靠性需要进一步评测，不保证每次复杂任务成功。
- 使用保守UTF-8字节预算而非真实tokenizer；长资料会有少量片段被预算裁掉。
- 界面导出/重命名已有接口或构建测试，但不是全量跨浏览器视觉/交互回归。
- 本机较高swap未做干净基线归因。索引与聊天会因单模型加载限制产生切换等待。

## 终端只读免确认与结果优先验收（2026-11-26）

- 依据反馈：只看信息别让用户点确认；只有真改系统配置/删文件的才确认；确认卡写清
  “执行后有什么影响”，命令折叠给懂命令的人展开；AI 回复先给关键结果。
- 真实模型复测“查一下我电脑cpu的型号”：`uname -m` 被确定性归一化成
  `sysctl -n machdep.cpu.brand_string`，只读自动执行（approval 记
  `{"auto_readonly": true}`），结果为“CPU 型号：Apple M5 Pro”，命令与原始输出
  都收在折叠区；真实浏览器复核卡片顺序为 结果 → 查看原始输出 → 查看命令 → 技术记录。
- 真实模型复测“在 /tmp 新建一个文件…写入 hello”：生成 `echo 'hello' > /tmp/...`，
  auto_run=false，卡片列出“执行脚本，可能改动文件 / 可能写入或覆盖文件 /
  可能访问网络”，未点确认即取消，文件未创建。
- 回环检查：保存计划后即使绕过界面直接调 repo.confirm，涉及写文件的计划仍被拒，
  只读计划被标记 auto 后也不接受重复确认；执行前再次校验 all_read_only。
- 自动滚动修复：后台标签页 rAF 会被暂停，改用定时器 + ResizeObserver 跟随；
  真实浏览器刷新首屏 scrollTop 即贴近底部，提交新需求后仍停在新结果。
- 局限不变：白名单只证明该调用本身只读，不代表命令之外的账号文件/网络不可达；
  未白名单的 exec 仍要求确认；无OS沙箱、无sudo/密码/PTY。
